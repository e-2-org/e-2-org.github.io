The Story of Art is Emma Kay’s history of art, from the first marks made by humans to the end of the twentieth century, written from memory. e-2 made it with her as an animated wall projection: sentences, wrapped into short justified paragraphs, travel towards the viewer from a point just above the centre of the screen, rest there briefly, then accelerate past and off the bottom of the screen. Each section heading leaves by the top. Over nine and a half hours the piece speeds up, imperceptibly, until only the occasional word can be read.

Why SVG

For Emma Kay’s previous piece with e-2, The Future from Memory, the text was animated in Flash. Every change to the text meant rendering it again as 3D vector shapes, importing them into Flash and fitting them into the right frames. For The Story of Art, the artist’s text was likely to be edited right up to the opening, so e-2 needed a way to make the whole piece again from a text file in a single step. SVG, the web’s format for vector graphics, made that possible: the piece is written as text, so it can be generated by a program. It also keeps the letters sharp when projected 25 feet wide. Video was considered, but its resolution was too low and every edit would have meant an expensive re-edit.

How the original worked

  • The text and its timing were held in a database, through a tool written in PHP. Each section had a speed at its start and at its finish, in sentences a minute, and the time each paragraph took was worked out between the two. That is how the piece speeds up.
  • The tool wrote the piece out as SVG files. In each file, a script (ECMAScript, the language now called JavaScript) wrapped every sentence into a justified paragraph, and SMIL animation, the animation built into SVG, moved it: growing from nothing to its resting size as it travelled down from the vanishing point, then growing to twenty times that size as it left the screen. Curves called splines eased each movement, so the paragraphs slow into place and accelerate away.
  • The text was set in an SVG font embedded in the files. It is Arial, converted. Drawing the letters from the font’s outlines let them grow smoothly, rather than jumping between pixel sizes as ordinary text does.
  • The piece was split into a series of files, each loading the next when it finished. As one document, the text (over 120,000 words at the time) took more than three minutes to lay out on the 2.8GHz Xeon computer bought for the project, and keeping it in memory left too little power for the animation, which dropped frames at the higher speeds. The version shown at Tate Modern is eight files.
  • It played in Adobe’s SVG Viewer, a browser plugin, at 1024 × 768 pixels.

Why it stopped working

Adobe stopped supporting its SVG Viewer in 2009, and modern browsers don’t run plugins. Browsers now display SVG themselves, but the original files fail in three ways:

  • They don’t open. The files use links (xlink:href) without declaring the namespace they belong to, which Adobe’s viewer allowed and browsers reject.
  • The layout fails. The script that wraps the text read its settings from style values that aren’t valid CSS, such as a font size with no unit. Browsers now discard them, so every position came out as “not a number”.
  • The font is unsupported. Of today’s browsers, only Safari still supports SVG fonts.

Finding the text that was shown

The archive holds two versions of the piece. The Tate version, eight files, matches the final text exactly. A second set of 102 files is a different, probably earlier, edit: 6,355 paragraphs running 9 hours 49 minutes, against the Tate version’s 5,812 and 9 hours 30 minutes. Up to about 1980 the two follow the same sections, though the Tate text often joins sentences into longer paragraphs. After 1980 the Tate version has a single run of 2,847 paragraphs, artists in alphabetical order under the heading PAINTING, ending with “The kitchen is fully functional if minimal.” The earlier edit has about twenty themed sections instead. The redevelopment uses the Tate version, in the order it was played at the Tate. (As archived, its seventh file loops back to the first instead of going on to the eighth, which was corrected at the Tate itself.)

The browser version

The redevelopment, in 2026, reads the Tate files and keeps everything that defines the piece in one data file: each paragraph’s text, size and line spacing, the timing and easing of its two movements, and the outlines of the 83 letters of the font that the text uses. A new player draws any moment of the piece from that data. It is a faithful port of the original layout script and animation, with three differences:

  • Only one paragraph is in the page at a time, so the player can run for nine and a half hours, and loop, without using more memory.
  • The letters are drawn from the original font’s outlines, as shapes, and spaced with the font’s own widths, as Adobe’s viewer did. An earlier version used ordinary browser text, and its animation stuttered: browser text snaps to whole pixels, so as it grows, letters and spaces jump a pixel at a time. Measured over 40 moments of the first sentence zooming in, browser text stayed still for 8 of 39 steps and then jumped; the shapes changed smoothly at every step. This is the problem the original solved by using an SVG font. It also means that no fonts need to be installed.
  • The eight files play as one sequence, without the original’s gaps for loading.

The original script placed the last line of each paragraph too far to the left, by double the amount it should have; Adobe’s viewer must have compensated for this, and modern browsers don’t. The player puts the last line where it was intended, in line with the rest of the paragraph. As in the original, the text is black on white, and the layout is measured on a 12-pixel letter size, the viewer’s default.

The video

The video is made from the browser version. A program opens the player in a browser without a window (headless Chrome), draws each frame at its exact moment in the piece and passes it to the video encoder, so the rendering doesn’t have to keep up with real time and no frame is dropped.

  • Shape. The composition is 4:3, but the projection was masked at the Tate, to a 25 × 15 foot screen. The video is 16:9, which crops the top and bottom of the composition; even the tallest paragraph fits inside it.
  • Sections. The piece is rendered as 72 videos, split at each section heading, several at a time. They share one frame timing, so they join exactly into the full piece without re-encoding. Each section also has a still, taken as its heading grows on its way out.
  • Time. The whole piece, a little over a million frames, took just under four hours to render, rendering five sections at a time.

The code is in the storyofart repository on GitHub.
